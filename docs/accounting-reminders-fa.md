# یادآوری سررسید حسابداری

این قابلیت در پروژه‌های فعلی و همان DentalContext قرار دارد؛ پروژه یا Context جدیدی ندارد.

## استفاده

در پنل حسابداری، بخش چک‌ها یا جدول اقساط، ابتدا «فعال‌سازی اعلان» و سپس «ارسال آزمایشی» را بزنید. ستون یادآوری برای انتخاب ردیف‌هاست. انتخاب هر حسابدار یا ادمین فقط برای حساب خودش ذخیره می‌شود؛ پیش‌فرض همه خاموش هستند. خطای ذخیره، وضعیت تیک قبلی را حفظ می‌کند.

برای موارد انتخاب‌شده، یک روز قبل و روز سررسید، از ساعت ۹ صبح تهران ارسال انجام می‌شود. پردازش هر دقیقه بررسی می‌کند و نیازی به بازبودن صفحه ندارد. اگر سرور ساعت ۹ خاموش بوده، در ادامه همان روز ارسال جبران می‌شود؛ روزهای گذشته بازپخش نمی‌شوند. تاریخ‌های ذخیره‌شده UTC طبق قرارداد فعلی سیستم به روز تهران تبدیل می‌شوند.

نمایش داخل برنامه سراسری است: کامپوننت `shared/ui/accounting-reminder-alert` در ریشه برنامه قرار دارد و در همه مسیرها اعلان دارای دکمه مشاهده و بستن نشان می‌دهد؛ به صفحه چک و اقساط وابسته نیست. اعلان هنگام تغییر مسیر باقی می‌ماند و با خروج یا تغییر حساب پاک می‌شود. دریافت تکراری همان یادآوری کارت تکراری ایجاد نمی‌کند. این نمایش از اعلان سیستم‌عامل مستقل است و از همان پیام Web Push تغذیه می‌شود. پیام آزمایشی هم در همین نمایش سراسری ظاهر می‌شود.

چک غیرمنتظر، قسط پرداخت‌شده یا حذف‌شده و پرونده غیرفعال ارسال ندارند. برداشتن تیک یا تغییر مجوز دریافت‌کننده در بررسی بعدی اثر دارد. تغییر سررسید، روز یادآوری را تغییر می‌دهد. یادآوری چک ضمانت صرفاً یادآوری است و مجوز وصول ایجاد نمی‌کند.

## ساختار برای بازبینی

- `Domain/Accounting/Reminders`: مدل انتخاب، سابقه ارسال، قاعده زمان تهران و قرارداد Repository.
- `ApplicationService.Contract/Accounting/Reminders`: Query و Command.
- `ApplicationService/Accounting/Reminders`: کنترل دسترسی، Handlerهای سبک و هماهنگی ارسال.
- `Infrastracture/Accounting/Reminders`: EF mapping، خواندن اسناد فعال، ذخیره تنظیم‌ها و قفل ارسال.
- `API/Controllers/Accounting/AccountingRemindersController`: مسیرهای API.
- `API/BackgroundServices/Accounting`: میزبان زمان‌بندی؛ منطق سناریو داخل Application است.
- فرانت `pages/accounting-dashboard/reminders`: API، وضعیت انتخاب‌های صفحه و فعال‌سازی Push.

ارسال از همان IPushNotificationService و subscriptionهای موجود کاربر استفاده می‌کند. مسیر و tag اعلان حسابداری جدا هستند؛ کلیک اعلان به همان ردیف چک یا قسط می‌رود. وضعیت یادآوری‌های هر صفحه با یک درخواست گروهی دریافت می‌شود.

## API

- `GET /api/accounting/reminders?kind=Cheque&ids=1&ids=2`، حداکثر ۱۰۰ شناسه، نتیجه شناسه‌های فعال کاربر جاری.
- `PUT /api/accounting/reminders/{Cheque|Installment}/{id}`، بدنه `{ "enabled": true }`.
- `POST /api/accounting/reminders/test`، ارسال آزمایشی به کاربر جاری.

نقش Admin یا Accountant و مجوز مشاهده حسابداری در سرور بررسی می‌شوند. هویت دریافت‌کننده از توکن می‌آید؛ دریافت‌کننده دلخواه از کلاینت پذیرفته نمی‌شود.

## راه‌اندازی

پس از SQL حسابداری قبلی، `docs/sql/2026-11-24-accounting-due-reminders.sql` را دستی اجرا کنید، سپس نسخه جدید بک‌اند و فرانت را منتشر کنید. اسکریپت شامل دو جدول و ایندکس‌های آن‌هاست و اطلاعات مالی را تغییر نمی‌دهد. Migration فقط ساخته شده و روی دیتابیس اجرا نشده است. کلیدهای VAPID، HTTPS، اجازه اعلان دستگاه و اجرای دائمی سرور برای ارسال لازم‌اند.

## ثبت ارسال و محدودیت تحویل

کلید یکتا شامل انتخاب، روز سررسید و روز یادآوری است. قفل اتمیک ده‌دقیقه‌ای از پردازش هم‌زمان یک اعلان جلوگیری می‌کند. پذیرش توسط سرویس Push به‌عنوان ارسال ثبت می‌شود؛ شکست ارسال پس از پانزده دقیقه قابل تلاش مجدد است. قفل پردازش متوقف‌شده نیز منقضی می‌شود. تغییر مبلغ یا خاموش/روشن کردن تیک، اعلان ارسال‌شده همان روز و همان سررسید را تکرار نمی‌کند.

پذیرش Push اثبات مشاهده توسط کاربر نیست. اگر فرآیند بعد از پذیرش Push و پیش از ثبت نتیجه متوقف شود، ارسال مجدد ممکن است؛ tag ثابت سمت مرورگر اعلان همان مورد را جایگزین می‌کند. ارسال دقیقاً یک‌باره به دستگاه قابل تضمین نیست. ارسال آزمایشی و دریافت واقعی روی محیط مستقر باید توسط کاربر بررسی شود؛ تست‌های خودکار پیام واقعی ارسال نمی‌کنند.
