# تغییرات لازم بک‌اند برای گردش کار رزرو جدید

این سند قرارداد مورد انتظار فرانت پس از حذف مرحله «بررسی زمان رزرو توسط منشی» و حذف دسترسی منشی به «تکمیل پرونده بیمار» را مشخص می‌کند.

## ۱. حذف بررسی زمان رزرو توسط منشی

- وضعیت و فیلدهای `secretaryReservationReviewStatus`، `secretaryReservationReviewedAt`، `secretaryReservationReviewerUserId` و `secretaryReservationReviewNote` از مدل رزرو، DTOها، نگاشت‌ها و دیتابیس حذف شوند.
- پارامترهای `reservationReviewStatus` و `onlyPendingReservationReview` از `GET /Reservation/SecretaryReservations` حذف شوند.
- endpoint قدیمی `POST /Reservation/ReviewSecretaryReservation` و request/response آن حذف شود.
- رزرو جدید دیگر در انتظار تایید زمان توسط منشی قرار نگیرد و برای معتبر یا قابل‌ویرایش بودن، وابسته به وضعیت بررسی منشی نباشد.
- migration دیتابیس باید ستون‌ها، indexها، constraintها و داده/enumهای مختص این گردش کار را حذف کند.

## ۲. ویرایش زمان توسط مشاور

- منبع واحد تغییر زمان، `PUT /Reservation` توسط مشاور مالک رزرو است؛ درخواست شامل `reservationId`، `consultantProfileId` و `reservationAt` جدید است.
- endpoint باید مالکیت رزرو را کنترل کند، زمان آینده را بپذیرد و قواعد ظرفیت را اعمال کند.
- هر شرطی که ویرایش مشاور را به تایید یا بررسی زمان توسط منشی محدود می‌کند حذف شود. قواعد مستقلِ لغوشدن رزرو و نهایی‌شدن بررسی حضور همچنان می‌توانند مانع ویرایش شوند.
- هیچ command جداگانه‌ای برای «تایید زمان فعلی» لازم نیست.

## ۳. حذف تکمیل پرونده توسط منشی

- نقش `Secretary` نباید مجوز فراخوانی `POST /Reservation/CompletePatientProfile` را داشته باشد؛ policy/handler مربوط به دسترسی منشی حذف یا صریحاً رد شود.
- تکمیل پرونده، در صورت نیاز محصول، فقط در گردش کار مشاور انجام می‌شود. پاسخ رزرو می‌تواند `requiresPatientProfile` را برای مشاور نگه دارد، اما داشبورد منشی نباید به آن وابسته باشد.
- فیلدهای غیرضروری `insuranceName`، `emergencyPhoneNumber`، `birthDate` و `notes` از request تکمیل پرونده و DTOهای نمایش پرونده حذف شوند. فرم فعلی مشاور فقط اطلاعات پایه ثبت‌نام شامل نام، نام خانوادگی، موبایل، رمز عبور و جنسیت را ارسال می‌کند.
- migration دیتابیس، ستون‌ها و نگاشت‌های فیلدهای حذف‌شده را نیز (در صورت نبود مصرف معتبر دیگر) پاک کند.

## ۴. مواردی که باقی می‌مانند

گردش کار مستقل تایید حضور تغییر نمی‌کند: مشاور حضور/عدم حضور را اعلام می‌کند و منشی از طریق `POST /Reservation/ReviewAttendance` ادعای مشاور را بررسی می‌کند.
